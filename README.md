# IP-finder

IP-finder отдаёт IPv4-адреса по коду страны. Это HTTP-сервис на FastAPI:
префиксы берутся из открытых данных RIPEstat, разворачиваются в адреса и
возвращаются потоком JSON. Тело ответа не собирается в памяти целиком, поэтому
даже страны с десятками миллионов адресов отдаются без роста потребления памяти.

Внутри лежит пайплайн с клиентами RIPEstat, Cert Spotter и Shodan; в HTTP-API
сейчас выведен только маршрут по стране, остальные источники доступны как
функции модулей.

> [!IMPORTANT]
> Код страны или найденный IP не подтверждают право проверять, сканировать или
> атаковать соответствующий ресурс. Используйте сервис только для собственных
> систем либо при наличии явного разрешения владельца.

## Возможности

- `POST /rep`: код страны → IPv4-адреса в JSON.
- Без `count` возвращаются все адреса страны; с `count` — первые N. Флаг
  `truncated` показывает, что список обрезан.
- Тело ответа собирается и отдаётся порциями, без материализации всего списка
  адресов в памяти.
- Вложенные префиксы отбрасываются до разворачивания, поэтому один адрес не
  попадает в ответ дважды, а итоговый размер известен заранее.
- Кэш ответов источников (7 дней) и повторы запросов с паузой.
- В ответе только IPv4: IPv6-префиксы не разворачиваются.
- Docker-режим разработки: код смонтирован в контейнер, uvicorn запущен с
  `--reload` и подхватывает правки.

## Требования

- Docker с плагином Compose (`docker compose`) — для запуска в контейнере;
- либо Python 3.10+ для локального запуска (в образе Python 3.13; сервис
  проверялся на Python 3.14);
- доступ к `stat.ripe.net`.

## Пример запроса

```bash
curl -s http://127.0.0.1:8000/rep \
  -H 'Content-Type: application/json' \
  -d '{"country": "LI", "count": 3}'
```

```json
{"country":"LI","count":3,"truncated":true,"addresses":["5.34.248.1","5.34.248.2","5.34.248.3"]}
```

Без `count` сервис вернёт все адреса страны — у больших стран это могут быть
десятки миллионов значений. Для пробных запросов задавайте `count`.

## API

### `POST /rep`

Поля запроса:

| Поле | Обязательное | Описание |
| --- | --- | --- |
| `country` | да | код страны из двух латинских букв, регистр не важен |
| `count` | нет | сколько адресов вернуть; целое число ≥ 1 |

Поля ответа:

| Поле | Описание |
| --- | --- |
| `country` | код страны в верхнем регистре |
| `count` | сколько адресов в этом ответе |
| `truncated` | `true`, если адресов у страны больше, чем запрошено |
| `addresses` | IPv4-адреса строками |

Коды ответа:

- `200` — успех;
- `422` — тело запроса не прошло проверку: код страны не из двух букв, `count`
  меньше единицы или в теле есть лишние поля (опечатка в имени поля не
  игнорируется);
- `502` — источник не ответил или вернул некорректные данные.

## Как это работает

1. `sources.country()` запрашивает у RIPEstat список ресурсов страны: сети
   IPv4/IPv6 и номера AS.
2. `normalize.merge()` выбрасывает сети, целиком вложенные в другие, — адреса
   не пересекаются, и точное количество известно заранее.
3. IPv6-префиксы не разворачиваются: в ответ попадают только IPv4.
4. `normalize.iter_from()` обходит диапазоны потоково, без списка в памяти; в
   сетях /0–/30 адрес сети и широковещательный адрес пропускаются, сети /31 и
   /32 отдаются целиком.
5. `fetch.fetch_json()` ходит в источники с четырьмя попытками, экспоненциальной
   паузой и учётом `Retry-After`; успешные ответы кэшируются.
6. Обработчик отдаёт JSON порциями по мере обхода адресов.

## Кэш и настройка

Ответы источников лежат в `data/cache/` — по файлу на запрос, вместе со временем
получения. Срок жизни записи — 7 дней; в пределах этого срока повторные запросы
не уходят в сеть.

Каталог данных можно переопределить переменной окружения `IPFINDER_DATA` или
необязательным файлом `.env` в корне проекта (переменные окружения приоритетнее
файла). Шаблон — [`.env.example`](.env.example).

## Состав проекта

```text
IP-finder/
├── docker/
│   ├── Dockerfile          образ на python:3.13-slim, uvicorn на порту 8000
│   └── docker-compose.yml  проброс портов, монтирование кода
├── scripts/
│   ├── build.sh            docker compose up -d --build
│   ├── start.sh            docker compose up -d
│   └── stop.sh             docker compose down
├── src/
│   ├── main.py             FastAPI-приложение, маршрут POST /rep
│   ├── requirements.txt    закреплённые версии зависимостей
│   └── pipeline/
│       ├── fetch.py        HTTP с ретраями и файловым кэшем
│       ├── normalize.py    сети, потоковый обход, DNS-разрешение
│       ├── sources.py      RIPEstat, Cert Spotter, Shodan
│       └── store.py        кэш, курсоры и запись результатов
├── init.sh                 меню из скриптов каталога scripts/
└── .env.example            пример настройки каталогов
```

Модули пайплайна умеют больше, чем сейчас открыто по HTTP: `sources.py`
работает с анонсированными префиксами ASN, именами из Certificate Transparency
(Cert Spotter) и поиском Shodan; `normalize.py` умеет параллельный DNS-резолв;
`store.py` — курсоры и пофайловую запись результатов. В API эти возможности
пока не выведены.

## Решение проблем

- **`502 источник не ответил`** — проверьте доступ к `stat.ripe.net` и повторите
  позже; успешные ответы уже лежат в кэше.
- **Порт 8000 занят** — поменяйте проброс в `docker/docker-compose.yml`,
  например на `"8001:8000"`.
- **Ответ слишком большой** — задайте `count`; без него отдаются все адреса
  страны.
- **`init.sh` печатает `No such file or directory`** — в нём осталась ссылка на
  удалённый `scripts/lib/common.bash`; на работу меню это не влияет.
