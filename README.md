# IP-finder

Поиск IP-адресов бесплатными источниками. Без Docker, без баз данных: чистый Python,
venv и обычные текстовые файлы. Результат прогона — **один текстовый файл**, строка
на запись.

## Что умеет

Два независимых маршрута:

- **По стране** — RIPEstat отдаёт префиксы страны, пайплайн разворачивает их в адреса.
  Пример: `LI`, `DE`.
- **По домену** — certspotter отдаёт имена из CT-логов (включая поддомены), имена
  резолвятся в IP-адреса. Пример: `--ct example.org`.

Прогон по стране продолжается с места остановки: последний записанный адрес лежит
в маленьком файле-курсоре, поэтому повторный запуск не начинает работу заново.

## Требования

- Linux, Python **3.10+** (проверено на 3.14).
- Доступ в интернет: `stat.ripe.net` и `api.certspotter.com`.
- Больше ничего. Ни MySQL, ни Docker, ни системных пакетов.

## Быстрый старт

```bash
cd IP-finder
./init.sh
```

`init.sh` — меню: показывает пронумерованный список скриптов и запускает выбранный.
Для первого запуска хватит двух шагов:

```bash
./init.sh 4     # создать venv и поставить зависимости (один раз)
./init.sh 6     # проверить окружение и доступность источника
```

Дальше — сама работа:

```bash
./init.sh 7     # поиск по стране
./init.sh 8     # поиск по домену через CT-логи
```

Скрипты можно вызывать и напрямую, минуя меню: `bash scripts/40_run_country.sh DE`.
Номера пунктов меню зависят от набора скриптов — актуальные всегда видны в самом меню.

## Куда попадает результат

Прогон пишет **один текстовый файл**:

- по стране — адрес в строке, например `5.34.248.1`;
- по домену — `адрес<TAB>имя`, например `104.20.26.136	example.org`.

По умолчанию имя файла — `out/<маршрут>_<дата-время>.txt`, а полный путь печатается
в конце прогона строкой `# файл: ...`.

Своё имя задаётся флагом `--out`, а `--append` дописывает в существующий файл —
так удобно вести всё в одном месте:

```bash
bash scripts/40_run_country.sh LI --out out/все-адреса.txt --append
```

Если прогонов уже много, слить их в один файл можно скриптом
`scripts/prod/20_merge_outputs.sh`: он складывает все `out/*.txt` вместе и убирает
дубликаты (`sort -u`), результат — `out/all.txt`.

## Меню и конвенция скриптов

`init.sh` собирает меню сам, сканируя `scripts/**/*.sh`. От каждого скрипта он читает
две строки-шапки:

```bash
#!/bin/bash
# ORDER: 40
# DESC: Поиск по стране (LI, DE, ...), аргументы пробрасываются в src.main
```

- `ORDER` задаёт порядок внутри своей папки (если строки нет — скрипт уедет в конец).
- `DESC` — подпись в меню.
- Папка скрипта задаёт группу, порядок групп: `dev` → `db` → `.` → `prod`.

Чтобы добавить свой скрипт, положите его в `scripts/` (или в подпапку) с шапкой из
`ORDER` и `DESC` — он появится в меню при следующем запуске. Файлы не с расширением
`.sh` (например, служебная библиотека `scripts/lib/common.bash`) в меню не попадают.

Запуск по номерам: `./init.sh 4 6` выполнит скрипты 4 и 6 по очереди.

## Флаги

Общее для обоих маршрутов:

- `--limit N` — сколько строк напечатать на экран (по умолчанию 200).
- `--max-addresses N` — остановиться после N адресов; **в CT-маршруте это число имён**.
- `--out ФАЙЛ` — куда писать результат; `--append` — дописывать, а не заменять.
- `--no-save` — не писать файл, только показать на экране (курсор не трогается).
- `--no-cache` — не читать и не писать кэш ответов источников.

Только для маршрута по стране:

- `--per-prefix N` — сколько адресов брать из каждой сети (0 = все IPv4).
- `--no-ipv6` — не разворачивать IPv6.
- `--restart` — начать заново, игнорируя курсор.

Только для маршрута по домену:

- `--ct ДОМЕН` — включает CT-маршрут. Вместе с кодом страны не сочетается:
  если переданы оба, победит `--ct`.

Примеры:

```bash
# Лихтенштейн: 5 адресов из каждой сети, без записи
bash scripts/40_run_country.sh LI --per-prefix 5 --no-save --limit 20

# Германия: продолжить с курсора, без IPv6, результат в файл
bash scripts/40_run_country.sh DE --no-ipv6 --out out/de.txt

# Домен: имена из CT-логов, разрешить в IP, записать
bash scripts/50_run_ct.sh --ct example.org --max-addresses 200
```

**Про размеры.** Без `--per-prefix` и `--max-addresses` маршрут по стране разворачивает
весь IPv4 страны: у Лихтенштейна это ~104 тысячи адресов, у Германии — десятки миллионов
строк. Для знакомства ставьте лимиты. IPv6 целиком не разворачивается никогда — на сеть
берётся не больше 32 адресов, иначе обход не закончился бы.

**Про дедупликацию.** Реестр отдаёт и агрегаты, и вложенные в них куски, поэтому перед
обходом сети, целиком вложенные в другие, отбрасываются — иначе один адрес попал бы
в файл дважды. Соседние, но не вложенные сети остаются раздельными: `--per-prefix`
считается от каждой сети, и склеивать их значило бы менять смысл флага.

## Где что лежит

Все служебные данные — обычные текстовые файлы рядом с проектом:

- `out/` — результаты прогонов.
- `data/cache/` — ответы источников в формате JSON, со временем загрузки. Кэш живёт
  7 дней (`MAX_AGE` в `fetch.py`), сбойные ответы в него не пишутся.
- `data/state/` — курсоры продолжения, по файлу на маршрут; внутри просто адрес.

Ничего из этого не обязательно хранить: удалите `data/` — следующий прогон создаст
всё заново, просто источники придётся опросить ещё раз. Каталоги можно вынести в другое
место через `.env` (`IPFINDER_OUT`, `IPFINDER_DATA`) или переменные окружения.

## Все скрипты

Главные (`scripts/`):

- `10_install.sh` — создать `.venv` и установить зависимости из `requirements.txt`.
- `20_setup_env.sh` — создать `.env` с путями к `out/` и `data/` (необязательный шаг).
- `30_check.sh` — проверить Python, venv, права на запись в каталоги и доступность
  источников.
- `40_run_country.sh` — поиск по стране. Без аргументов делает безопасный пробный прогон
  (LI, 12 адресов, без записи).
- `50_run_ct.sh` — поиск по домену через CT. Без аргументов — пробный прогон на
  `example.org`.
- `60_test.sh` — тесты.
- `70_show_results.sh` — показать последний файл из `out/`.

Разработка (`scripts/dev/`):

- `10_python_shell.sh` — Python-REPL с уже импортированными `normalize`, `sources`, `store`.
- `20_syntax_check.sh` — проверить синтаксис всех `.py`.
- `30_clean_caches.sh` — удалить `__pycache__`.

Боевые прогоны (`scripts/prod/`):

- `10_full_country_run.sh` — полный прогон страны, спрашивает страну, файл и
  подтверждение; требует терминал.
- `20_merge_outputs.sh` — слить все `out/*.txt` в один файл без дубликатов.

## Тесты

```bash
bash scripts/60_test.sh
```

75 тестов: разбор ответов источников, стомиллионные диапазоны без материализации,
возобновление с курсора, чистка вложенных сетей, файловое хранилище и кэш. Ни базы,
ни сети не требуется: сеть и каталоги подменяются моками и временным каталогом.

## Если что-то не работает

- **`нет venv`** — выполните `scripts/10_install.sh`.
- **`источник не ответил`** — скрипт вернёт код 1 и напечатает причину. У certspotter
  без API-ключа около 10 запросов на окно, у RIPEstat ограничения мягче: подождите
  и повторите, ответы уже полученных запросов лежат в кэше.
- **Прогон «висит»** — скорее всего, разворачивается большая сеть без лимитов. Прервите
  Ctrl+C и добавьте `--per-prefix` или `--max-addresses`: файл и курсор остаются
  согласованными, прогон продолжится с того же места.
- **Файл результата пустой** — источник ответил, но адресов не нашлось (пустая страна
  или домен без CT-записей). Смотрите сводку в stderr: там число имён, сетей и адресов.
- **`python src/main.py` не работает** — так и задумано. Запускать нужно только как модуль
  (`python -m src.main`), скрипты делают это сами.

## Отличия от исходного проекта

Перенесён только пайплайн discovery, и в нём убрана база:

- **MySQL больше нет.** Активы, кэш ответов и курсоры, которые раньше жили в трёх
  таблицах, теперь обычные файлы: результат — текстовый файл, кэш — JSON, курсор —
  строка с адресом. SQLite тоже не понадобился: файлы проще и остаются текстом.
- **Дедупликация переехала из базы в код.** Раньше повторяющиеся адреса гасил первичный
  ключ `assets`, теперь вложенные сети отбрасываются до обхода (`normalize.merge`).
- **Появились `--out` и `--append`**, а `--no-save` теперь означает «не писать файл».
- **Обёртка Acunetix API не переносилась**: она не относится к поиску адресов
  и в исходном репозитории сейчас нерабочая.

## Правовая заметка

Инструмент ищет адреса по открытым источникам и предназначен для работы с ресурсами,
на которые у вас есть разрешение: собственные сайты, согласованный аудит, исследования.
Ответственность за цели, объём запросов и соблюдение правил источников и закона лежит
на запускающем. Полная версия дисклеймера — в README исходного проекта.
